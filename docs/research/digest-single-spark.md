# Single-Spark DSV4.1-Flash deployments: digest

R1 = https://github.com/vcruz305/DSV4.1-Flash-1017-EXL3-Spark-recipe (vLLM fork, EXL3 1.62 bpw, same pack class as ours)
R2 = https://github.com/0xBakeer/deepseek-v41-flash-spark (PyTorch+Triton, native FP4 experts, resident "keep-set" + NVMe)
All paths below are `/blob/main/<path>`.

## R1: EXL3 1.62 bpw on vLLM, TP1 (README.md, docs/ENGINEERING_NOTES.md)
- **Decode:** 140.0-145.6 ms/step, 4.14-4.74 accepted tok/step, **29.5-34.0 tok/s** single stream (bench7, 512 tok). Ladder: no draft 13.4 tok/s (74.4 ms/tok); DSpark k=6 + whole-layer alias 13.5; + cold-expert ATS alias 24.2; + tile-K 16 + k=5 31.3-34.0; + TP1 decode tiles 141.4 vs 144.8 ms/step.
- **Step anatomy (nsys, 2,657 kernels/step):** MoE 84.0 ms (58%), non-MoE linears 36.6, glue 8.5 (1,502 launches at 5.7 us), head 5.7 (2 passes at 2.86), draft MoE 6.1, other ~10. MoE kernel: 1 CTA/SM, 47.6% DRAM peak, **integer-issue bound (~4 int instr/weight in trellis decode)**, spills at 255 regs, L2 hit 77%.
- **Prefill:** chunk 2112 (`--max-num-batched-tokens 2112 --long-prefill-token-threshold 2047`, threshold must be chunk-6). Varied text ~**720 tok/s** (533 at 1.6K, 963 at 24K); log text 1,005-1,179 tok/s from 32K to 225K, flat with depth. Chunk 4096 **halves** prefill (446 vs 718); 8192 OOMs.
- **Context:** `--max-model-len 229376`, needle retrieved at 32K/131K/225K; TTFT 196 s at 225K; decode at depth 26.5-31.5 tok/s. Raising maxlen 32K->229K costs ~3% short-prompt. 1M not measured.
- **Concurrency:** `--max-num-seqs 1`, CUDA graphs `FULL_DECODE_ONLY` sizes 1..7 (+11-14%).
- **KV:** `--kv-cache-memory-bytes 1 GiB`, bf16 (`auto`); vLLM reports 236,089 tok at 32K, 760,070 at 229K (3.31x one request). **Prefix caching off** ("measured off"; reason not stated - uncertain).
- **Memory (121.7 GiB):** engine reservation 110.5 GiB; steady MemAvailable ~4.0 GiB (32K) / 3.7-3.8 (229K); min 2.98 GiB during 225K prefill; 0 swap. RoPE cache trimmed to maxlen frees 0.484 GiB (`VLLM_DS41_ROPE_TRIM_MAX_POS`).
- **Cold-expert offload:** 1,380 least-routed experts (routing-frequency selection, not calibration) + embedding gathered into one 64-B-aligned **8.59 GiB side file**, GPU reads via read-only mmap over **ATS** (unified memory). Membership: configs/cold-alias-selection.json - my count: only layers 0-3 and 10-29 (15-79/layer); none in 4-9 or 30-39. Whole-layer aliasing (38/39+MTP) was ATS-slow: ~10% of aliased experts touched/step, read at **~6.6 GB/s**, ~130 ms of a ~292 ms step. Side file depends on **page cache**: making MTP experts resident (+2.8 GiB) left 1.2 GiB free, page cache collapsed -> 9.5 tok/s.
- **Engram:** `--engram-config {"table_memory":"disk","disk_resident_scales":false,"projection_tp":true}`, io_uring reader (needs `seccomp=unconfined`, `label=disable`, `memlock=-1`). No IO/token numbers.
- **DSpark:** k=5, greedy draft, block rejection, `VLLM_DS41_MARKOV_NVFP4=1` (7.6->11.2 tok/s structured, at the time). k=6 +1.5 ms for +0.04 tok/step; k=7 +17 ms for +0.55; "re-sweep if step < ~120 ms". Acceptance swings 3.4-5.5 run to run; per class: prose 137.6-139.7 ms/step, code 143-150.6, structured 142-146.
- **Host:** `vm.compaction_proactiveness=0 vm.watermark_boost_factor=0 vm.swappiness=0`, `swapoff -a && swapon -a`, `sync; drop_caches=1` before boot (scripts/serve.sh). Guard (scripts/guard.sh): kill at **MemAvailable < 0.5 GiB** or swap growth > 64 MiB, sampled at 0.05 s (0.25 s overshot by 90 MiB). `--shm-size=2g`, `GPU_MEM_UTIL=0.90`.
- **Gotcha:** a boot right after ~10 GB writes to a 97%-full disk ran 509.5 ms/step and 253 tok/s prefill for its whole life. Cause not isolated. Keep the NVMe quiet.
- **Lost:** all-resident (OOM at load); `__launch_bounds__(256,2)` -49% (90 KiB dyn smem, so no 2 CTA/SM); `MOE_SH_STAGES 4` (+4% in model despite -11% microbench); `MOE_SMS_PER_EXPERT 4` +84%; `L2_PREFETCH` (8.7 ms of nothing); adaptive verification -3.5%; split-K overlay (dead even); tilelang split-K failed correctness (78% top-1).
- **Ranked next (to reach 46 tok/s, need -42 ms):** 1) bit-exact cheaper trellis decode (-25-30 ms); 2) non-MoE linears, wo_b 1.8x off peak (-8-12); 3) glue fusion (-3-4); 4) head second pass (-2-3).

## R2: FP4 keep-set + NVMe streaming (README, RESULTS, LIMITATIONS, docs/*)
- **True streaming lost.** 25.6% resident (73.8 GB, 3,926 slots): **2.64-2.71 tok/s**, hit 0.83, **0.92 GB NVMe/token**, ~2.5 GB/s effective; attention+Engram+MoE kernel <8% of time. Best unpruned streaming 3.5 tok/s. NVMe O_DIRECT, 18.8 MB experts: 4.1 GB/s at QD1, 5.4 at 8, 5.6 at 32. Expert must be read as **2 runs** (1.1 MB scales + 17.7 MB weights); 6 reads collapse to ~0.6 GB/s. Nothing overlapped reads with compute; router-lookahead/DSpark prefetch never tried (LIMITATIONS.md).
- **What ships is pruning:** router masked to a per-layer keep-set (`substitute` mode). Keep 0.36 = 139/layer, ~80-81 GB arena (3-bit CB3, 14.45 MB/slot), hit rate 1.0, zero expert IO. Speed ~145 ms/step, **17-37 tok/s** (HTML 36.6, SQL 31.8, JS 28.2, Python 24.3, prose 17.1). Prefill 337 tok/s (5K prompt), 87 tok/s if streaming.
- **Selection:** routing trace (36,250 tok, 190 seqs, `results/trace-union`); per-topic histograms in coverage.json; final recipe = **saliency** (gate_w x ||expert out||, REAP) + **maxmin** water-filling over topics. Uniform per-layer N beats global ranking (+0.025/+0.041 nats). Coverage < ~0.7 => degeneration; corpus must contain each register (markup coverage 0.03 -> `<!DOCTYPE>` loops). 6-10 topics fit; 14+ fail gate (4/16, 2/15, 4/39). Coding/general top-25% Jaccard 0.11-0.31.
- **Coverage curve (static / LRU per token / per 6-token block):** 4,000 experts 0.674/0.855/0.769; 6,000 0.797/0.921/0.874; 8,000 0.884/0.959/0.934. Distinct experts per layer per 6-token verify block: **20.96** measured (trace 18.2-29.5, mean 22.6). Prefill touches 370-381/384 experts per layer, so prefill misses need a separate **transient ring >= 384 slots** (smaller wraps inside a layer = silent 0.88 rel error).
- **Engram:** buffered `pread` (2 per row: 256 B + 8 B), `POSIX_FADV_RANDOM`, thread pool, dict cache 200k rows/table (~53 MB). 48 rows/token (~12.7 KB), addresses known from token ids. 3,792 rows in 0.65 s; ~16 ms/step, hidden by background threads.
- **KV:** 3,200 B/token (4 source layers 2/8/14/20) + 180 MB constant SWA rings: 1.0 GB at 256K, 3.5 GB at 1M. **KV is not the limit; prefill scratch is:** 7.2 GB per 2,048-token chunk + 15.1 KB/token of context (11.2 GB at 256K). Keep 0.40 died at 195K prefill (MemAvailable 0.8 GB, 582 s); 0.36/81 GB holds a filled 256K. Validated max_seq 131,072 (256K only for 0.36).
- **DSpark:** block 6 (5 drafted). Per accepted token 41.0 / 39.7 / 39.7 ms at block 4/6/8. Acceptance: markup ~5, code 3.5-4.7, prose 2.5, thinking 2.66-2.9. Drafter is +7.2 GB of resident FP4 experts. Batch = 1, serialised requests.
- **Prefill levers:** Decoder SWA Bounded Replay (layers 21-39 only over last 128 tokens, by CED) -41%; 2048 chunks another -52%.
- **Lost / refuted:** teacher-forced loss as a quality gate (CB3 scored better and still looped; the real cause was a trace corpus with no markup, and CB3 ships again); top-k 5 (-8.3 ms, +0.025 nats prose); 2-bit cold tier (~3 ms gain, +0.047 prose); FP4 shared experts; FP4 head; bf16 router gate (11-31% wrong experts; **router must be fp32**); fused attention; `drop` mode 0/6; topk=4; penalties, no-repeat-ngram, low effort, temp 0; global ranking; graph merging (41->3 replays, -0.6 ms). Kept: FP4 attn/wo_a, FP8 head, split-K fp32 HC-mix.
- **Host gotchas:** box hard-hangs (no OOM kill) near MemAvailable 0; **watchdog `os._exit` at < 2.5 GB for 3 s**; start refuses below 90 GiB free; `torch.cuda.mem_get_info()` counts page cache as used (reported 32 GB free with 99.9 GiB available), so use MemAvailable; never set container `--memory`; a second resident process wedged the box twice.

## Takeaways for TensorFold (inference, not measured by either repo)
1. R1 is our configuration on vLLM: **~141 ms/step, 30-34 tok/s, 1 slot, 1 GiB KV** is the bar. Its MoE is integer-issue bound, so trellis decode cost is the main lever.
2. Expert streaming from NVMe is dead for decode (R2: 2.6 tok/s). Small ATS/mmap cold sets work only if the page cache keeps them hot (R1: 1,380 experts, ~9%).
3. Context and slots are limited by **prefill scratch and the MemAvailable floor**, not KV (3.2 KB/token native). Budget per-chunk scratch explicitly. Bigger chunks hurt R1 (4096 halves prefill) but help R2 (fewer chunk-level expert passes).
4. Neither repo measured concurrency > 1, prefix caching benefit, or Engram IO/token under load.
